大模型分布式训练并行策略

大模型训练的本质不只是把计算摊到更多 GPU 上，而是把 Transformer 的不同维度映射到不同 GPU，并控制由此产生的通信、显存占用、流水线空泡与负载不均衡。

从一个 Decoder-only Transformer 的输入张量出发：

X∈RB×S×HX\in\mathbb{R}^{B\times S\times H} X∈RB×S×H

其中 BBB 是 Batch Size，SSS 是 Sequence Length，HHH 是 Hidden Size。若模型有 LLL 个 Transformer Layer，MoE 层有 EEE 个 Expert，则可以把现代大模型并行理解为沿以下几类维度进行切分：

B⏟DP×S⏟CP/SP×H⏟TP×L⏟PP×E⏟EP\underbrace{B}_{DP} \times \underbrace{S}_{CP/SP} \times \underbrace{H}_{TP} \times \underbrace{L}_{PP} \times \underbrace{E}_{EP} DPB​​×CP/SPS​​×TPH​​×PPL​​×EPE​​

并行策略 核心切分维度 主要解决问题 典型通信
数据并行 DP Batch 提高吞吐、扩展训练规模 AllReduce / ReduceScatter / AllGather

Hugging Face 的 Model Parallelism 把 TP 描述为对 Tensor 的“横向切分”，PP 描述为沿 Layer 的“纵向切分”；进一步组合 DP、TP、PP 后，就得到经典的 3D Parallelism。

并行训练的通信问题·

统一的 α-β 通信模型·

分布式通信耗时可以近似写成：

Tcomm=αNmsg+βVT_{comm}=\alpha N_{msg}+\beta V Tcomm​=αNmsg​+βV

其中：

  • α\alphaα：每次通信的启动延迟；
  • NmsgN_{msg}Nmsg​：消息或 Collective 的次数；
  • β\betaβ：单位字节传输时间，可以近似理解为带宽倒数；
  • VVV：实际传输的数据量。

这意味着通信瓶颈存在两个完全不同的方向。

一类是 Latency Bound：Tensor 不大，但 Collective 调得非常频繁，例如高 TP Degree 下每层频繁执行 Collective；另一类是 Bandwidth Bound：通信次数不多，但一次要搬运大量参数、梯度或 Token，例如 DP Gradient Reduce、FSDP Parameter AllGather、MoE AllToAll。

以 Ring AllReduce 为例，对大小为 MMM 的 Tensor，在 NNN 个 Rank 上每个 Rank 的理论通信量约为：

VAR=2N−1NMV_{AR}= 2\frac{N-1}{N}M VAR​=2NN−1​M

原因是 Ring AllReduce 可以拆成：

AllReduce=ReduceScatter+AllGather\text{AllReduce}=\text{ReduceScatter}+\text{AllGather} AllReduce=ReduceScatter+AllGather

每一半的数据量约为：

N−1NM\frac{N-1}{N}M NN−1​M

Visible Communication·

完全消灭通信通常不现实。更实际的目标是让通信与计算重叠：

Tstep≈Tcompute+Tvisible_comm+Tbubble+TimbalanceT_{step}\approx T_{compute}+T_{visible\_comm}+T_{bubble}+T_{imbalance} Tstep​≈Tcompute​+Tvisible_comm​+Tbubble​+Timbalance​

如果通信能被 GEMM、Attention 或 Backward 覆盖，那么即使总字节数没有下降，端到端训练时间也可能明显下降。

因此很多工程优化的本质都是：

Tvisible_comm→0T_{visible\_comm}\rightarrow 0 Tvisible_comm​→0

数据并行 DP·

DP 的实现机制·

Data Parallelism 的基本思想最简单：每张 GPU 保存相同的完整模型，数据拆成多份不同 GPU 处理不同的数据。因此 DP 主要解决吞吐问题，不能解决单卡模型显存的问题

如果模型参数为 θ\thetaθ，初始化时

根据统一的 α\alphaα-β\betaβ 通信模型，不能每算出一个参数梯度就执行一次 AllReduce，DP 会把多个 Gradient 放进一个 Bucket，满了之后执行 AllReduce(bucket).

需要平衡的是

ZeRO / FSDP·

传统 DDP 最大的问题是每个 Rank 都保存完整 Parameter、Gradient 与 Optimizer State。ZeRO/FSDP 在仍然保持数据并行语义的前提下，把训练状态按 DP Rank 分片。

ZeRO-3 / FSDP 的 Forward 典型流程是：

Backward 则需要再次恢复参数，并用 ReduceScatter 聚合并重新分片梯度。因此 ZeRO/FSDP 的本质是：

Memory↓⟺Parameter/Gradient Communication↑\text{Memory}\downarrow \quad\Longleftrightarrow\quad \text{Parameter/Gradient Communication}\uparrow Memory↓⟺Parameter/Gradient Communication↑

Hugging Face 的 Model Parallelism 用了一个非常形象的比喻：每个参与者只背一部分装备，需要使用某层时临时共享并重建完整参数，用完后再释放。

DP 的优缺点·

优点：模型计算图基本不需要修改；GPU 之间在 Forward/Backward 主体中相互独立；扩展到更多节点相对容易；通信可以通过 Gradient Bucket 与 Backward 高度重叠。

缺点：普通 DDP 不降低模型状态显存；DP Degree 过大时 Global Batch 容易变得过大；使用 FSDP/ZeRO-3 后虽然显存下降，但 Parameter AllGather 与 Gradient ReduceScatter 增加了通信压力。

张量并行 TP·

数据并行 DP 是 模型复制、数据切分；张量并行 TP 是 数据共享、模型切分，也就是说把一个 Transformer Layer 内部的大矩阵拆到多张 GPU 上，让多张 GPU 共同完成同一个样本的计算。

TP 的通信特征·

TP 的最大问题不是总通信量，而是通信发生在 每一层的 Critical Path 上：

几十甚至上百层会不断重复这一模式。因此 TP 需要非常快的网络，实践中通常尽量不要把一个 TP Group 跨越慢速节点互联。TP 应优先放进 NVLink/NVSwitch 域，并只扩到足够解决单层显存与计算问题的程度。

TP Degree 继续增大时，每个 Rank 上 GEMM 变小，Tensor Core 利用率下降，而 Collective Latency 并不会同比下降，最终会出现 Scaling Saturation。

流水线并行 PP·

如果 Transformer 的层数较多，单张 GPU 放不下，PP 把 Transformer 的层沿深度分到不同 Stage：

Stage 之间只需要传 Boundary Activation，Backward 再反向传递 dActivation。

1F1B 与 Interleaved Pipeline·

Forward 与 Backward 的方向正好相反

Forward Stage 之间传递的是 ActivationActivationActivation，而 Backward Stage 之间传递的是 ∂L∂Activation\dfrac{\partial L}{\partial Activation}∂Activation∂L​.如果所有 MIcro Batch 全部 Forward 完成再统一 Backward，会导致 Activation Memory 很大

现代训练通常使用 1F1B：在 Steady State 中一个 Stage 交替执行 Forward 和 Backward，避免一次保存所有 Micro-Batch 的 Forward Activation。

进一步使用 Virtual Pipeline / Interleaved 1F1B，可以让一个 Physical Stage 持有多个不连续 Layer Chunk，从而降低 Bubble，但代价是更多 P2P 调度与更复杂的 Activation 生命周期。
